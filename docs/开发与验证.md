# 开发与验证

## 基线与执行边界

抽离基线为宿主 `c768cb12c86e59b60fbc69149013850edce509b0`，当前修复版本 `1.0.1` 已正式发布。已发布的 `1.0.0` 公开 GMM sources 变体存在冲突，原 Tag 和制品保留。平台/API 合同见[功能与平台差异](功能与平台差异.md)，对外安装见 [README](../README.md)。本仓不改变工具链、SDK 或业务行为；维护任务只在其独占 Worktree 中写入。

组件 SDK 重任务统一通过受信 CI 的 `ci.py component-run`（`verify` / `package`）登记 profile 执行，遵守当前 Mac worker 锁与预算。CI 参数、准确固定提交、资格与受控执行合同以 [GY CrossKit 统一远程验证](https://github.com/gycrosskit/.github/blob/main/docs/统一远程验证.md)和该文档指向的 Gitee CI 手册为准。新组件必须先完成 profile 登记，不能用候选仓库中的任意命令绕过统一入口。

下列 Gradle 命令是 **profile 的执行清单**，供受控 runner 采用，不是在候选 checkout 手工重编译的替代入口。JDK 21；Android SDK 36 / minSdk 24；Native 使用宿主现有 OHOS fork 工具链，iOS 需合格 Xcode/Simulator。资源不足、签名/SDK 缺失和测试跳过必须明示，不能通过减小发布平台集合规避。

## 轻量检查

```sh
python3 scripts/test-archive-prebuilt.py
python3 scripts/test-jitpack-metadata.py
python3 scripts/test-check-maven.py
bash -n scripts/archive-prebuilt.sh jitpack-install.sh
git diff --check
```

归档测试使用 Gradle/metadata checker 替身，只验证版本准入、覆盖保护、命令合同、真实 tar 和 SHA256；metadata/checker 回归使用真实临时文件验证损坏文件、变体、sidecar、许可证与字节码拒绝。它们不证明 SDK 编译、KSP 或网络行为。

## 源码与运行时回归（受控 runner）

```sh
bash gradlew --no-daemon --max-workers=1 :routing-core:jvmTest :routing-core:testDebugUnitTest :routing-compiler:test :routing-core:iosSimulatorArm64Test
bash gradlew --no-daemon --max-workers=1 :routing-core:compileDebugKotlinAndroid :routing-core:compileKotlinIosSimulatorArm64 :routing-core:compileKotlinOhosArm64
```

`iosSimulatorArm64Test` 对应 Apple Silicon；使用 Intel Mac 时匹配 `iosX64Test`。须读取 JUnit 的实际执行数、失败与 skip；`UP-TO-DATE` / `FROM-CACHE` 如实记录，零用例不算通过。OHOS compile 不等于设备或链接验收。

## 打包、冻结与产物验证（受控 runner）

统一 builder 固定执行 `VERSION=1.0.1 bash scripts/archive-prebuilt.sh`。该入口要求 `build/maven` 和同名输出归档尚不存在，保护旧候选与失败证据；统一入口须分配空任务目录，不在当前任务中自动清理覆盖旧字节。脚本依次执行：

1. `bash gradlew --no-daemon --max-workers=1 -Dorg.gradle.parallel=false publishAllPublicationsToStagingRepository`。
2. `scripts/jitpack-metadata.py` 正规化 `build/maven/com/github/gycrosskit/routing`，移除 JVM `sourcesElements` 及既有不兼容变体；sources JAR 保留原文件，不将主 JAR 改成源码包。
3. 标准 `scripts/check-maven.py` 校验 group、version、完整 publication 集合、真实文件、许可证、变体与四种 sidecar。
4. 生成 `build/prebuilt/routing-maven.tar.gz` 和 `.sha256`；不上传、不 Tag、不公开发布。

精确 group：`com.github.gycrosskit.routing`。顶层 artifact：`routing-core,routing-compiler`。必须包含以下完整 publication，不能删除未构建目标的 metadata 来伪造成功：

```text
routing-core,routing-core-android,routing-core-jvm,routing-core-iosarm64,routing-core-iossimulatorarm64,routing-core-iosx64,routing-core-ohosarm64,routing-compiler
```

Native 目标集合：`ios_arm64,ios_simulator_arm64,ios_x64,ohos_arm64`。运行时 AAR/JAR 字节码目标为 JVM 11（major 55）。`routing-compiler` 为 JVM 21（major 65），因此全归档 checker 上限设 65；core 的 Android/JVM 目标仍显式锁定 11，不能把该上限理解为手机运行时要求 21。

手工核查命令（仍由受控 runner 使用）：

```sh
python3 scripts/check-maven.py build/maven com.github.gycrosskit.routing 1.0.1 routing-core,routing-compiler ios_arm64,ios_simulator_arm64,ios_x64,ohos_arm64 routing-core,routing-core-android,routing-core-jvm,routing-core-iosarm64,routing-core-iossimulatorarm64,routing-core-iosx64,routing-core-ohosarm64,routing-compiler --max-jvm-major 65
```

## 独立 Maven 消费（受控 runner）

`verification-consumer` 是独立 Gradle 工程：没有 project 依赖、复合构建和 MavenLocal。`routingMavenRepo` 用独占仓库规则固定本组件解析来源；候选缺失即失败，不回退旧远程版本。版本通过 `routingVersion` 固定，默认已发布的 `1.0.1`。

私有冻结候选：

```sh
bash gradlew -p verification-consumer --no-daemon --max-workers=1 -ProutingVersion=1.0.1 -ProutingMavenRepo=/ABSOLUTE/FROZEN_MAVEN compileDebugKotlinAndroid compileKotlinIosSimulatorArm64 linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64 jvmTest
```

公开消费在发布后使用新的消费工作区和干净依赖缓存，省略 `MavenRepo` 参数从 JitPack 下载同一版本，并执行相同目标；记录真实解析来源、源码/Tag SHA、CI/helper、Run 与制品摘要。私有 staging 消费、JitPack 构建完成、公开 metadata 字节完整性、公开三端消费与真机分别验收。

JitPack 只运行 [jitpack-install.sh](../jitpack-install.sh)，下载该不可变版本的 Release Maven 归档，按 [release-checksums.txt](../release-checksums.txt) 的真实 SHA256 验证后安装相同字节；没有摘要必须失败。该表已登记 `1.0.1` 的真实归档摘要，并保留 `1.0.0` 的原摘要；未登记版本仍必须失败，不能复用旧归档摘要、写假摘要或拉取 `latest`。
